# Parallel World Game Rules

This file is the single authoritative source of gameplay behaviour. Product scope is defined by `docs/product/PRODUCT.md`; implementation must not invent mechanics that conflict with either document. All constants in this file are initial, tunable balancing values unless explicitly marked invariant.

## 1. Authority and invariants

1. Deterministic rules decide which action occurs, its actor and target, all scores, timing, eligibility, state transitions, and outcomes.
2. AI generates only natural-language wording for a persisted, already-decided action. AI output cannot create or alter actions, targets, reactions, relationship values, romantic outcomes, reputation, followers, memories, or time.
3. Every bounded value is clamped after each event. Unless stated otherwise, bounded values are integers from 0 through 100.
4. Every random choice uses a persisted deterministic seed. Identical world state, rule version, simulation interval, and seed produce identical mechanical results.
5. Every significant action produces an auditable event or history entry before text generation.
6. Every state-changing rule is idempotent. Reprocessing the same idempotency key returns the existing result without applying changes twice.
7. All actors, records, seeds, events, and idempotency keys are scoped to one `WorldId`. No rule reads from or writes to another world.
8. Persistent timestamps are UTC. Character-local time is display and schedule context only.

## 2. Common simulation concepts

| Concept | Definition |
|---|---|
| Game time | The world's authoritative simulated clock. MVP default progression is one game minute per real minute while the world is Active. |
| Real time | UTC elapsed time used to determine how much game time is eligible to advance. It never substitutes for persisted game time. |
| Simulation tick | One active-world evaluation interval. MVP ticks represent 15 game minutes; an empty tick persists no actions. |
| Simulation run | One idempotent attempt to process a closed game-time interval for one world under one rule version and run seed. |
| Catch-up simulation | Bounded, compressed processing from `LastSimulatedGameTime` toward the eligible current game time without evaluating every missed minute. |
| Deterministic random seed | A stored value from which all random substreams are derived. It is not generated by AI. |
| Actor | A world-owned entity allowed to originate or receive simulation actions. |
| Player actor | The one human-controlled actor in a world. Rules apply consequences to player actions, but the simulator does not invent player-authored actions. |
| AI character actor | A rule-controlled character eligible for autonomous actions. |
| Action | A mechanical intent with actor, target, type, inputs, selected parameters, scheduled time, and idempotency key. |
| Event | An immutable record that an action or state transition occurred or was rejected for a recorded reason. |
| Memory | A character-owned structured recollection derived from an eligible event. |
| Relationship event | An event applying bounded directional changes between two actors and optionally a romantic-status transition. |
| World event | A fictional, world-scoped event that may affect topics, moods, opinions, and trends. |
| Life event | A character-scoped career or personal event. |
| Cooldown | A persisted earliest-next-eligible game time for a rule, actor, target, or topic. |
| Idempotency key | A stable hash identifying one intended operation so retries cannot duplicate it. |
| Importance | A 0-100 measure of long-term significance. |
| Emotional impact | A signed value from -100 to 100; magnitude is intensity and sign is valence. |
| Visibility | `Private`, `Conversation`, or `World`. MVP has no cross-world or public visibility. |

## 4. Determinism, ordering, and universal rule contract

### Seed derivation

`RunSeed = Hash(WorldSeed, RuleVersion, IntervalStartUtc, IntervalEndUtc, RunOrdinal)`.

Each choice uses an order-independent substream:

`ChoiceSeed = Hash(RunSeed, RuleId, ActorId, TargetId-or-empty, TopicId-or-empty, StableOrdinal)`.

Candidate collections are sorted by stable identifier before scoring. A deterministic PRNG produces integer rolls from 0 through 99. Changing iteration order, worker count, or AI provider cannot change mechanics.

### Idempotency

State-changing operations use:

`IdempotencyKey = Hash(WorldId, RuleVersion, RuleId, IntervalStartUtc, IntervalEndUtc, ActorId, TargetId-or-empty, StableOrdinal)`.

The decision, mechanical event, relationship deltas, memories, notification intent, and text-generation intent share or reference this key. A retry loads the prior result. Partial runs resume after the last committed action; they do not reroll.

### Required rule fields

Every important rule below supplies: **Purpose, Inputs, Preconditions, Decision, Randomness, Limits, Cooldown, State changes, Persistence, Idempotency, Example, Status**. All formulas round half away from zero and clamp bounded outputs.

## 5. World time and simulation run

### Rule SIM-01: advance an active world

- **Purpose:** Advance one world without duplicate intervals.
- **Inputs:** World status, persisted game time, last simulated UTC time, current UTC time, rule version, world seed.
- **Preconditions:** World is `Active`; interval start equals persisted cursor; no completed run owns the interval.
- **Decision:** Eligible game-time delta is `floor(real elapsed minutes * GAME_TIME_SCALE)`. Process complete active ticks only. Runs use half-open intervals `[start,end)`.
- **Randomness:** Run seed and substreams defined above; time advancement itself has no roll.
- **Limits:** Active request work is bounded by configured run/action limits.
- **Cooldown:** `ACTIVE_TICK_MINUTES` between active evaluations.
- **State changes:** Advance simulation cursor only after all mechanical actions for the interval commit.
- **Persistence:** SimulationRun with interval, seed, rule version, status, action counts, cursor, and error reason.
- **Idempotency:** One run key per world/rule/interval; overlapping completed intervals are rejected.
- **Example:** With 31 elapsed real minutes and scale 1.0, two 15-minute ticks are eligible; one minute remains unprocessed.
- **Status:** MVP.

World states are `Paused`, `Active`, and `Archived`. Paused worlds accumulate no eligible game time. Resuming sets the real-time anchor to the resume UTC time and continues from persisted game time; paused real time is not caught up. Archived behaviour beyond read-only retention is deferred.

Character-local display time derives from persisted UTC plus a configured IANA/Windows-compatible display zone. Schedules use that local projection; persisted timestamps remain UTC. Daylight-saving ambiguity is resolved by UTC ordering, never by duplicate local intervals.

## 6. Character state

### Personality traits

Traits are integers 0-100. MVP traits are fixed after character creation.

| Trait | Influences |
|---|---|
| Humour | Humorous tone eligibility, playful replies, joke-topic weighting |
| Confidence | Initiation, public posting, disagreement, apology reluctance |
| Empathy | Support, helpful replies, apology acceptance, negative-impact reduction |
| Aggression | Confrontation, hostile tone, escalation, rivalry actions |
| Curiosity | Notice probability, new-topic selection, questions, opinion exposure |
| Honesty | Truthful stance, promise reliability, deliberate-deception avoidance; never bypasses secret rules |
| Sociability | Activity, follows, replies, messages, public-event participation |
| Ambition | Goal priority, career topics, influence-seeking actions |
| Patience | Delayed response tolerance, de-escalation, repetition resistance |
| Optimism | Positive tone, positive mood recovery, opportunity interpretation |
| Sensitivity | Mood and relationship response magnitude |
| Romantic openness | Romantic-goal eligibility and invitation/acceptance weighting |

Trait evolution is deferred. A future rule may change one trait by at most 1 point per 30 game days after a qualifying importance-80 life event, with an immutable trait-history event.

### Interests and opinions

Interest strength is 0-100. Opinion position is -100 to 100; confidence and intensity are 0-100. Topic relevance is 0-100.

For a qualified exposure:

`Resistance = clamp(round(0.6 * Confidence + 0.4 * Intensity), 0, 100)`

`Influence = clamp(round(0.6 * SourceTrust + 0.4 * ExposureStrength), 0, 100)`

`RawDelta = round(Direction * 10 * Influence/100 * (100-Resistance)/100)`

Ordinary total change is capped by `MAX_OPINION_CHANGE_PER_DAY`; major importance-80 world/life events use the major-event cap. A position with intensity at least 70 cannot cross zero from one ordinary exposure. Repeated opposing exposures, trusted actors, and major events can move it gradually. Each applied change records source, old/new position, confidence, and cap usage.

### Mood

Mood influences are `Happy`, `Sad`, `Angry`, `Excited`, `Anxious`, `Embarrassed`, `Lonely`, `Inspired`, `Calm`, and `Tired`. Each has intensity 0-100, source event, start, expected end, and linear decay rate. Multiple influences coexist; dominant mood is highest current intensity, ties resolved by earliest start then stable mood ID.

Event mood delta is `BaseImpact * (0.75 + Sensitivity/200)`, clamped to 0-100. Sleep deficit and out-of-schedule activity add Tired; sufficient scheduled rest decays it. Activation used by activity rules is high for Excited/Inspired/Angry, neutral for Happy/Calm, and low for Sad/Anxious/Lonely/Tired. Mood changes tone and likelihood, never eligibility or mechanical truth.

Default durations are tunable: Happy 6 hours, Sad 12, Angry 4, Excited 4, Anxious 8, Embarrassed 12, Lonely 24, Inspired 8, Calm 6, and Tired 12 or until a completed rest period. Current intensity is `round(InitialIntensity * RemainingDuration / InitialDuration)`. A qualifying new event may add a separate influence or extend the same source/type once; it cannot reset decay repeatedly without a new event.

Meaningful changes—new intensity at least 40, delta at least 20, or importance at least 60—persist a MoodHistory entry with cause. Ordinary mood influences expire; importance-80 influences may create a memory.

### Goals

Goals have type, target, priority 0-100, progress 0-100, status, success/failure conditions, and source. Supported goal types include GainFollowers, BecomeInfluencer, ImproveRelationship, FindRomanticPartner, RepairConflict, GetPromoted, StartBusiness, LearnSkill, BuildExpertise, and DamageRivalReputation.

| Goal | Success condition | Failure/abandonment condition | Release |
|---|---|---|---|
| GainFollowers | Persisted follower target reached | Deadline expires or target becomes invalid | Post-MVP synthetic growth; actual follows count in MVP |
| BecomeInfluencer | Influence and follower targets reached | Deadline expires | Deferred |
| ImproveRelationship | Selected dimensions/state reach recorded target | Target unavailable or sustained regression past deadline | MVP |
| FindRomanticPartner | Dating state reached through ROM-01/02 | Goal expires or romance becomes incompatible | MVP |
| RepairConflict | Qualifying repair event and Rivalry/Trust targets reached | Repair rejected repeatedly or deadline expires | MVP |
| GetPromoted | Eligible Promotion life event occurs | Career changes or deadline expires | Deferred |
| StartBusiness | Eligible StartBusiness event occurs | Goal abandoned or prerequisites lost | Deferred |
| LearnSkill | Structured skill progress reaches 100 | Goal abandoned | Deferred |
| BuildExpertise | Expertise target reached through qualified events | Goal abandoned or topic removed | Deferred |
| DamageRivalReputation | Auditable public-event target reached | Rivalry ends, action becomes ineligible, or deadline expires | Deferred |

MVP activates at most `MAX_ACTIVE_GOALS`. Goal conflict is resolved by highest priority, then earliest activation, then stable ID. Progress changes only from qualified events and is clamped. Completion, failure, and abandonment persist events. A goal may be abandoned after 30 game days without progress when its priority is below 40; important goals require an explicit superseding event. Complex career/business goals are deferred.

## 7. Character activity selection

### Rule ACT-01: select an autonomous actor and action family

- **Purpose:** Give eligible characters fair, bounded opportunities to act.
- **Inputs:** Activity level, sociability, dominant mood activation, schedule, profession, interests, goals, recent actions, relationship/world events, cooldowns, daily counts.
- **Preconditions:** AI actor belongs to world, world Active, actor not disabled, daily hard cap not reached, at least one eligible action family.
- **Decision:** `ActivityScore = clamp(0.35*ActivityLevel + 0.15*Sociability + 0.10*GoalRelevance + 0.10*MoodActivation + 0.10*EventRelevance + 0.10*InterestOpportunity + FairnessCredit - FatiguePenalty - RepetitionPenalty, 0, 100)`. Actor is inactive when deterministic roll is at least score. Eligible actors are sampled without replacement. `FairnessCredit=min(20,5*game days since last visible action)`; each same-day action adds 10 fatigue.
- **Randomness:** One actor roll and one weighted action-family roll from actor substreams.
- **Limits:** `MAX_ACTIONS_PER_CHARACTER_DAY`, global post cap, and per-action limits.
- **Cooldown:** Per action family. Quiet hours block non-urgent actions. Importance-80 events may bypass quiet hours but not hard daily caps.
- **State changes:** Reserve action slot and chosen action family.
- **Persistence:** Planned SimulationAction with score components, roll, seed, and rejection reason when diagnostically retained.
- **Idempotency:** Actor/interval/action ordinal key; duplicate family/target/topic checks occur before commit.
- **Example:** An active sociable character with a relevant goal scores 72; roll 31 permits action. A second action adds fatigue, reducing later likelihood.
- **Status:** MVP.

Quiet hours use character-local time. Profession/schedule marks `Sleeping`, `Working`, `Available`, or `Busy`; important events may create an override. High-activity characters cannot exceed caps, and fairness credit raises opportunities for recently quiet characters.

## 8. Social feed rules

### Rule POST-01: create a character post

- **Purpose:** Create a non-repetitive world-visible post from structured state.
- **Inputs:** Interests, opinions, mood, goals, world events, recent feed topics, activity level, cooldowns, daily counts.
- **Preconditions:** ACT-01 selected Post; actor is available; post/global caps and cooldowns permit; at least one eligible topic.
- **Decision:** Post score is `0.30*ActivityLevel + 0.20*Sociability + 0.15*GoalRelevance + 0.15*EventRelevance + 0.10*MoodActivation + 0.10*TopicNovelty`. Roll must be below score. Topic weights are interest 40%, goal 20%, eligible event 20%, opinion 10%, recent-feed response 10%. Stance comes from structured opinion; tone comes from mood/personality.
- **Randomness:** Deterministic post roll and weighted topic/tone substreams.
- **Limits:** `POST_MAX_CHARACTERS`, daily actor/world caps, one visibility value `World`.
- **Cooldown:** `POST_COOLDOWN_HOURS`; same topic blocked for `DUPLICATE_TOPIC_COOLDOWN_DAYS` unless importance at least 80.
- **State changes:** Create planned post and consume action/post slots.
- **Persistence:** Post action, decided topic/stance/tone/intent, source IDs, seed, AI request, and final/fallback text.
- **Idempotency:** Actor/topic/interval ordinal; identical retry returns the same post record.
- **Example:** A technology-interested Inspired character selects an active fictional technology topic; rules persist an optimistic stance before wording.
- **Status:** MVP. Hashtag enrichment is deferred.

AI receives actor voice attributes, decided topic, stance, tone, intent, maximum length, and up to the allowed memories. If generation fails or violates the contract, a deterministic template expresses the decision. AI cannot add a new target, claim an unrecorded event, or change stance.

### Rule REPLY-01: notice and reply

- **Purpose:** Decide whether and how an AI actor replies to an eligible post.
- **Inputs:** Mention flag, follow edge, topic interest, opinion agreement, directional relationship, mood, post age/depth, recent replies, goals.
- **Preconditions:** Actor is not post author; post belongs to world; depth below `MAX_REPLY_DEPTH`; actor has not replied to this post with the same intent; cooldown/caps permit.
- **Decision:** `NoticeScore = mention?100:clamp(25 + 0.25*TopicInterest + 0.15*Familiarity + (follows?15:0) - AgePenalty,0,100)`. If noticed, `ReplyScore=clamp(0.30*TopicInterest + 0.20*abs(OpinionPosition)/100*100 + 0.15*RelationshipRelevance + 0.15*MoodActivation + 0.10*GoalRelevance + 0.10*PostImportance - RepetitionPenalty,0,100)`. Both rolls must pass. Rules select Supportive, Neutral, Questioning, or Disagreeing stance; tone and intended emotional impact are persisted.
- **Randomness:** Separate notice and reply substreams; deterministic stance tie-break.
- **Limits:** Reply daily cap and depth cap. One negative reply to the same actor/topic per day.
- **Cooldown:** One actor/post reply; hostile exchanges also use `ARGUMENT_COOLDOWN_HOURS`.
- **State changes:** Planned reply and optional relationship-event intent.
- **Persistence:** Notice decision, reply decision, stance, tone, impact, target post, seed, text intent.
- **Idempotency:** Actor/post/intent key.
- **Example:** A direct mention guarantees notice, but a Tired actor may still decline a non-urgent reply when the reply roll fails.
- **Status:** MVP.

### Rule REACT-01: react, repost, quote, bookmark, or ignore

- **Purpose:** Choose compatible lightweight feed actions.
- **Inputs:** Interest, agreement, closeness, author reputation, mood, recent repeated reactions.
- **Preconditions:** Actor is not author; actor has no identical reaction on post; action is released for current version.
- **Decision:** MVP LikeScore is `0.30*Interest + 0.25*Agreement + 0.20*Affection + 0.10*AuthorReputation + 0.10*PositiveMood + 0.05*GoalRelevance - RepetitionPenalty`; like when roll is below score, otherwise Ignore. Post-MVP repost and quote scores add influence/goal relevance. Bookmark is player-only/private unless later approved.
- **Randomness:** One deterministic roll per compatible action.
- **Limits:** One Like; one of Repost or QuotePost. Like may coexist with one share action.
- **Cooldown:** No repeated action on the same post; daily action cap applies.
- **State changes:** Create/remove no reaction automatically; unfavourable mood produces Ignore, not a negative reaction.
- **Persistence:** Reaction/action or ignored-decision diagnostic with components.
- **Idempotency:** Actor/post/action-type unique key.
- **Example:** High interest and agreement yield score 78; roll 22 creates one Like. Retry returns it.
- **Status:** Like/Ignore MVP; repost, quote, bookmark deferred.

### Rule FOLLOW-01: follow or unfollow

- **Purpose:** Maintain world-local follow edges from sustained relevance.
- **Inputs:** Familiarity, interest overlap, reputation, trust, affection, rivalry, qualified recent events, current edge.
- **Preconditions:** Distinct same-world actors; daily change cap and cooldown permit.
- **Decision:** Follow candidate requires Familiarity at least 20 and either InterestOverlap at least 40 or Reputation at least 70. `FollowScore=0.25*Familiarity+0.25*InterestOverlap+0.20*Trust+0.15*Affection+0.15*Reputation`; follow only when score is at least 60 and the deterministic roll is below the score. Unfollow requires Rivalry at least 60, Trust at most 25, or three qualified negative events in seven days; one minor event is insufficient.
- **Randomness:** Deterministic follow/unfollow roll after threshold eligibility.
- **Limits:** `MAX_FOLLOW_CHANGES_PER_DAY`; follower count never below zero.
- **Cooldown:** Follow/unfollow `FOLLOW_COOLDOWN_DAYS`; re-follow `REFOLLOW_COOLDOWN_DAYS`.
- **State changes:** Add or end Follow edge.
- **Persistence:** FollowChanged event with score, reasons, actor, target, and prior edge.
- **Idempotency:** Actor/target/desired-state key.
- **Example:** Familiarity 45 and overlap 70 qualify; score 63 and roll 40 creates the edge.
- **Status:** MVP.

## 9. Private messaging

### Rule MSG-01: character-initiated message

- **Purpose:** Initiate a relevant one-to-one conversation.
- **Inputs:** Shared interest, player achievement, relationship check-in, apology/conflict, secret/promise, romantic interest, world event, unresolved conversation, urgency, schedule, relationship.
- **Preconditions:** Post-MVP feature enabled; same-world player/character conversation; topic known to character; relationship requirement for topic satisfied; quiet-hour and daily limits permit unless urgency at least 80.
- **Decision:** Score is `0.25*RelationshipRelevance + 0.20*TopicRelevance + 0.20*Urgency + 0.15*GoalRelevance + 0.10*Sociability + 0.10*MoodActivation`; roll must pass 60. Rules select reason, topic, intent, and permitted knowledge.
- **Randomness:** Deterministic initiation and topic rolls.
- **Limits:** `MAX_UNSOLICITED_MESSAGES_PER_DAY`.
- **Cooldown:** Topic cooldown and quiet hours.
- **State changes:** Persist planned message before text generation.
- **Persistence:** Message action, reason, knowledge references, intended impact, AI/fallback text.
- **Idempotency:** Actor/conversation/topic/interval key.
- **Example:** A kept promise importance 80 permits an urgent thank-you during quiet hours if daily cap remains.
- **Status:** Deferred by PRODUCT.md.

### Rule MSG-02: reply eligibility and timing

- **Purpose:** Decide whether an AI character replies and, when enabled, when.
- **Inputs:** Message intent/urgency, schedule, sleep/work state, closeness, mood, unresolved conflict, recent messages.
- **Preconditions:** Valid same-world conversation and recipient knowledge; no existing planned reply for source message.
- **Decision:** `ReplyScore=clamp(35 + 0.20*Urgency + 0.20*Familiarity + 0.15*Trust + 0.15*Comfort + 0.10*Sociability - ConflictAvoidancePenalty,0,100)`. MVP processes an eligible reply without simulated delay; a failed roll records NoResponse. Deferred delay is 0-`MAX_PLANNED_REPLY_DELAY_HOURS`, increased by Sleep/Work/Tired and reduced by urgency/closeness.
- **Randomness:** Deterministic eligibility roll and, when enabled, delay substream.
- **Limits:** One reply plan per source message; no full-history AI input.
- **Cooldown:** Conversation repetition/topic cooldown; follow-up after 24 hours only when an unresolved promise/urgent intent remains.
- **State changes:** `Planned` reply is persisted before wording; later becomes Completed, FallbackCompleted, or NoResponse.
- **Persistence:** PlannedReply with due time, decision reasons, selected memories, and source message.
- **Idempotency:** Source-message/recipient key.
- **Example:** A work-state recipient gets an eligible reply; MVP generates it now, while deferred timing would persist a four-hour due time first.
- **Status:** Eligibility/reply MVP; delayed timing and character follow-up deferred.

## 10. Relationship system

Relationships are directional. A-to-B and B-to-A are updated only by event rules that explicitly affect each direction.

### Initial values

For newly introduced actors: Familiarity 10, Trust 50, Respect 50, Affection 20, Comfort 15, Commitment 0, Rivalry 0, Jealousy 0. Attraction is `clamp(10 + round(0.30*Compatibility) + SeededOffset[-5,5],0,40)`. Compatibility and preferences are structured inputs; if romance is disabled or incompatible, Attraction is 0.

Fear is not an MVP relationship dimension because PRODUCT.md does not require it. Adding Fear later requires an accepted product/rules change, defined event impacts, and migration of existing relationships.

### Rule REL-01: apply a relationship event

- **Purpose:** Apply auditable bounded directional deltas.
- **Inputs:** Event type, actor/target, base matrix row, severity, personality, mood, relationship state, public/private context, repetition count.
- **Preconditions:** Valid same-world actors; source event committed; event not previously applied.
- **Decision:** `FinalDelta=round(BaseDelta * SeverityMultiplier * PersonalityMultiplier * MoodMultiplier * ContextMultiplier * RepetitionMultiplier)`. Multipliers are bounded: severity 0.5-2.0, personality 0.75-1.25, mood 0.85-1.15, context 0.75-1.25, repetition 0.5-1.25.
- **Randomness:** None after source event is decided.
- **Limits:** Ordinary/severe per-event caps and ordinary daily cap; values clamp 0-100. Severe importance-90 events may use the severe cap and bypass daily ordinary cap once.
- **Cooldown:** Source-action cooldowns; repeated argument cooldown.
- **State changes:** Update dimensions, derived labels, romantic evaluation flags, and cap ledger.
- **Persistence:** RelationshipEvent with base/final deltas, modifiers, old/new values, source and idempotency key.
- **Idempotency:** Unique source-event/rule/direction key.
- **Example:** Public insult Trust -5 with severity 1.5 and public context 1.2 becomes -9 before caps.
- **Status:** MVP.

| Repeated argument | +2 | -4 | -3 | -3 | -2 | -4 | -2 | +5 | +1 |
| Jealous behaviour | +1 | -3 | -2 | -1 |  | -3 | -1 | +2 | +6 |
| Support during life event | +3 | +5 | +4 | +4 | +1 | +4 | +1 | -1 |  |
| Unfollow |  | -2 | -1 | -2 |  | -1 |  | +1 |  |
| Re-follow | +2 | +1 |  | +1 |  | +1 |  | -1 |  |

Public negative events multiply Respect loss and Rivalry gain by 1.25. Empathy reduces negative response to accidental harm; Sensitivity increases emotional dimensions. Repeated positive events of the same type after three in seven days use 0.5 repetition multiplier; repeated negative events use up to 1.25. No modifier can reverse a base delta's sign.

### Derived friendship states

These labels are derived, not the only stored truth. Priority is Enemy, Rival, active romantic label, BestFriend, CloseFriend, Friend, Acquaintance, Stranger.

| State | Exact derivation |
|---|---|
| Stranger | Familiarity < 15 |
| Acquaintance | Familiarity >= 15 and no higher state |
| Friend | Familiarity >= 40, Trust >= 40, Affection >= 35, Rivalry < 50 |
| CloseFriend | Familiarity >= 65, Trust >= 65, Affection >= 60, Comfort >= 55, Rivalry < 40 |
| BestFriend | Familiarity >= 80, Trust >= 80, Affection >= 75, Comfort >= 70, Rivalry < 25 |
| Rival | Rivalry >= 60 and Enemy criteria not met |
| Enemy | Rivalry >= 75, Trust <= 20, Affection <= 20 |

Ordinary passive decay is disabled in MVP to keep changes understandable. Deferred long-term decay may reduce Affection/Comfort by at most 1 per 30 inactive game days, never Trust from absence alone. Recovery requires qualifying positive events; values do not reset automatically.

## 11. Romance, conflict, and breakup

### Rule ROM-01: romantic eligibility and invitation

- **Purpose:** Decide who may invite whom and select a valid candidate.
- **Inputs:** Familiarity, Trust, Attraction, Comfort, romantic openness/preferences, active romantic state, goals, severe conflicts, cooldown, schedule.
- **Preconditions:** Both actors romance-enabled and compatible; F/T/At/C meet constants; RomanticOpenness meets minimum; no incompatible active relationship; no unresolved severe conflict in lookback; cooldown expired.
- **Decision:** `InitiationScore=0.30*Attraction+0.20*Trust+0.15*Comfort+0.10*Familiarity+0.10*RomanticOpenness+0.10*GoalRelevance+0.05*PositiveMood-ConflictPenalty`. Candidate with highest score at least 60 wins; ties use seeded stable tie-break. Date type is selected from shared interests and mutually available schedules.
- **Randomness:** Seeded tie-break/date-type choice; thresholds are not random.
- **Limits:** One pending invitation per pair and one active compatible romance per actor in MVP.
- **Cooldown:** `DATE_INVITATION_COOLDOWN_DAYS` after invitation or rejection.
- **State changes:** `None -> RomanticInterest -> InvitationPending` as needed.
- **Persistence:** Invitation decision, candidate scores, eligibility reasons, date type, due/expiry, timeline event.
- **Idempotency:** Initiator/candidate/cooldown-window key.
- **Example:** F60/T55/At68/C50/open70 qualifies; initiation score 64 creates a pending invitation before dialogue.
- **Status:** MVP.

### Rule ROM-02: accept or reject a date

- **Purpose:** Decide the invitation outcome before text.
- **Inputs:** Recipient Attraction, Trust, Comfort, Familiarity, openness, current mood, goal relevance, compatibility, recent positive/negative events.
- **Preconditions:** Pending unexpired invitation; eligibility remains valid; not already resolved.
- **Decision:** `AcceptanceScore=0.35*Attraction+0.25*Trust+0.15*Comfort+0.10*Compatibility+0.10*RomanticOpenness+0.05*GoalRelevance+MoodModifier-ConflictPenalty+SeededOffset`, where MoodModifier is -10..10 and SeededOffset is -5..5. Accept at `DATE_ACCEPTANCE_MIN`; otherwise reject with the highest-weight deterministic reason code.
- **Randomness:** Only bounded seeded offset/tie-break.
- **Limits:** Score clamped 0-100; one outcome.
- **Cooldown:** Invitation cooldown applies after either outcome.
- **State changes:** Accept: `InvitationPending -> Dating`; Reject: `InvitationPending -> None`. Rejection is an event, not a durable status.
- **Persistence:** DateAccepted/DateRejected event, score components, reason, memories, relationship impacts, timeline.
- **Idempotency:** Invitation ID/outcome rule key.
- **Example:** Score 58 plus seeded offset -2 rejects with LowComfort; AI phrases that recorded reason.
- **Status:** MVP.

### Dating progression

MVP states are `None`, `RomanticInterest`, `InvitationPending`, and `Dating`. Dating begins with Commitment raised to at least 20. Successful dates and relationship events may develop approved dimensions without activating a deeper lifecycle.

Deferred states are `FormerPartner`, `Committed`, `Engaged`, `Married`, `Separated`, and `Divorced`.

Arguments require a qualifying disagreement, insult, broken promise, jealousy event, or accumulated conflict. Escalation score uses Aggression, Angry mood, Rivalry, event severity, and repetition; de-escalation uses Empathy, Patience, Trust, apology, and time. One pair cannot start another argument during `ARGUMENT_COOLDOWN_HOURS`. Public conflict uses public modifiers. Apology requires an attributable harmful event; acceptance is rule-based. Any future romantic reconciliation is deferred and, if approved, must be a recorded rule event rather than AI wording.

### Deferred rule ROM-03: breakup and reconciliation

- **Purpose:** End unhealthy Dating states safely and permit later repair.
- **Inputs:** Directional Trust, Affection, Comfort, Commitment, recent conflict severity/frequency, neglect, incompatible goals, severe events.
- **Preconditions:** Inactive in MVP. When separately approved after MVP, breakup requires Dating. Reconciliation requires FormerPartner, cooldown expired, no unresolved severe event, Trust >=40, Comfort >=35, Attraction >=50, and a qualifying repair event.
- **Decision:** `BreakupPressure=0.40*(100-Trust)+0.25*(100-Commitment)+0.15*(100-Affection)+0.20*ConflictScore`. Break up at `BREAKUP_PRESSURE_MIN` on three daily evaluations within seven days, or immediately at pressure 80 after an importance-90 severe betrayal. Higher dissatisfied-direction pressure selects initiator. Reconciliation score uses 35% Trust, 25% Comfort, 20% Attraction, 20% repair quality and must reach 60.
- **Randomness:** Seeded tie-break only; no healthy relationship ends from one roll.
- **Limits:** One evaluation per pair/day; relationship impacts use caps.
- **Cooldown:** Reconciliation cooldown; argument cooldown.
- **State changes:** `Dating -> FormerPartner`; reconciliation uses `FormerPartner -> RomanticInterest`, followed by a new invitation path. It never silently restores the old state.
- **Persistence:** Pressure evaluations, Breakup/Reconciliation event, initiator/reasons, memories, status history.
- **Idempotency:** Pair/evaluation-day or repair-event key.
- **Example:** Pressure 69 for three evaluations triggers breakup; retry cannot create a second history entry.
- **Status:** Deferred. MVP stops at Dating and records only the invitation/outcome history required by PRODUCT.md. No FormerPartner re-entry, reconciliation cooldown, or repeated relationship cycling is active.

### Deferred engagement, marriage, separation, and divorce

These rules are inactive until PRODUCT.md release placement is decided. Initial design assumptions for later review: proposal requires Committed state, at least 30 game days in the relationship, Trust >=75, Commitment >=75, Comfort >=70, no severe conflict in 14 days, and a 30-day proposal cooldown. Acceptance is rule-based using the same persisted-decision pattern. Marriage requires Engaged for at least 14 days, Trust >=75 and Commitment >=80. Married may transition to Separated after sustained breakup pressure; Separated may reconcile to Married or transition to Divorced after a future minimum duration. Every proposal, acceptance/rejection, marriage, separation, reconciliation, and divorce is an immutable shared history event. These numbers are placeholders under Open Balancing Decisions, not active MVP behaviour.

## 12. Memory, secrets, and promises

### Rule MEM-01: create a memory

- **Purpose:** Preserve meaningful knowledge without recording every trivial interaction.
- **Inputs:** Source event, type, importance, emotional impact, subject, topic, participants, visibility, character knowledge.
- **Preconditions:** Character witnessed/received/was told the event; released MVP types are PersonalFact, Promise, Secret, Compliment, Insult, Conflict, SharedExperience, Achievement, RomanticEvent, and Rejection. Breakup, LifeEvent, and WorldEventReaction activate only with their deferred systems.
- **Decision:** Create when importance >= `MEMORY_CREATION_IMPORTANCE`, absolute emotional impact >=40, or a released mandatory type is Promise, Secret, or RomanticEvent. Breakup becomes mandatory only if that deferred lifecycle is activated. Merge only when same source fact and subject; do not merge distinct events.
- **Randomness:** None.
- **Limits:** Importance/confidence 0-100; emotional impact -100..100.
- **Cooldown:** Trivial same-topic events within one day reinforce at most once.
- **State changes:** Create or reinforce structured memory; never from AI text alone.
- **Persistence:** Memory with source event, knowledge provenance, confidence, visibility, expiry, recall count.
- **Idempotency:** Character/source-event/memory-type key.
- **Example:** A kept promise creates one Promise memory for both involved characters; retry reinforces nothing twice.
- **Status:** MVP.

### Rule MEM-02: score and recall memories

- **Purpose:** Select a small relevant context set for rules or wording.
- **Inputs:** Importance, recency, emotional magnitude, subject/topic/relationship match, recall frequency, confidence, access restrictions.
- **Preconditions:** Requesting character knows memory; secret visibility permits purpose/recipient; memory not expired or resolved beyond use.
- **Decision:** `RecallScore=0.25*Importance+0.15*Recency+0.15*EmotionalMagnitude+0.15*SubjectMatch+0.10*TopicMatch+0.10*RelationshipMatch+0.10*Confidence-RecallPenalty`. Recency is `max(0,100-2*ageDays)`; penalty is `min(20,2*recallsInLast7Days)`. Sort score descending then memory ID.
- **Randomness:** None.
- **Limits:** At most `MAX_MEMORIES_PER_AI_REQUEST`; full conversation history is never sent.
- **Cooldown:** Recall penalty discourages repetition.
- **State changes:** Increment recall metadata only after context is used; reinforce importance by at most +5 for a new importance-60 related event.
- **Persistence:** RecallSelection record referencing request and selected scores.
- **Idempotency:** AI request/character/memory selection key.
- **Example:** A high-importance recent promise outranks an old low-emotion compliment.
- **Status:** MVP.

Ordinary memories may expire after 30 days when importance <40 and never reinforced. Importance >=80, active promises, unresolved secrets/conflicts, relationship transitions, and major life events are permanent until an explicit resolution rule changes their status. Contradictory memories coexist and are marked Contested; structured confidence, provenance, and recency decide rule use. AI context may mention uncertainty but cannot resolve the contradiction.

### Secrets

A Secret records owner, subject, knowers, confidentiality 0-100, disclosure promise, provenance, and status. Disclosure eligibility requires the discloser knows it, a rule-selected recipient, and `DisclosurePressure > Confidentiality`, where pressure uses Aggression, low Honesty, low Trust toward owner, goal relevance, and event urgency. Accidental disclosure is a distinct low-intent event; deliberate disclosure is Betrayal. Both persist knowledge transfer before wording and apply the impact matrix. Secrets never cross worlds or enter logs. Secret recall excludes recipients not authorized by current knower state.

### Promise state and resolution

A Promise records creator, recipient, description code/template data, due condition/date, importance, and status. States are Active, Kept, Broken, Cancelled. Kept/Broken resolution occurs once when the due condition is evaluated; Cancelled requires mutual cancellation or invalidated condition before resolution. Resolution creates memories and relationship events. AI cannot declare a promise kept or broken without the rule event.

## 13. Reputation, influence, and followers

Reputation, Credibility, Influence, Popularity, Expertise, Kindness, and HumourReputation are separate 0-100 values only when the released feature needs them. Changes require public auditable events and are capped at 10 per value/day (20 for importance-90 events). Public context multiplier is 1.25; private events do not change public reputation unless a disclosure event makes them public. Deferred decay is at most 1 per 30 inactive days.

MVP follower count is derived exactly from active world-local Follow edges. It cannot be negative and does not invent synthetic followers. Post-MVP synthetic growth may be an auditable `SyntheticFollowerChange` action based on visibility, reputation, and trend participation, capped at 5% of current synthetic followers or 10 per day, whichever is greater; controversy/inactivity loss uses the same event requirement. Snapshots are caches, while follow edges and follower-change events remain authoritative.

## 14. Trends, world events, and life events

These systems are deferred except for seeded MVP topics used to exercise posting.

### Trend rule

Candidate score is `0.25*PostFrequency + 0.20*UniqueActorScore + 0.20*Engagement + 0.15*GrowthVelocity + 0.10*InfluencerParticipation + 0.10*WorldEventRelevance`, all inputs normalized 0-100. Start at `TREND_START_SCORE`, end below `TREND_END_SCORE` after minimum duration, snapshot every `TREND_SNAPSHOT_HOURS`. One active trend per normalized topic prevents duplicates. Trend decisions and snapshots are idempotent by topic/window.

### World-event rule

Categories are Technology, Entertainment, Sports, Economy, FictionalPolitics, Culture, and LocalIncident. A seeded weekly evaluation selects at most one eligible event when fewer than `MAX_CONCURRENT_WORLD_EVENTS` are active. Event templates define severity, duration, visibility, interested-character criteria, and bounded opinion/mood/trend impacts. States are Scheduled, Active, Ended, Archived, or Cancelled. MVP never imports real-world news.

### Life-event rule

Eligible types include NewJob, Promotion, JobLoss, Graduation, Moving, StartBusiness, Award, NewHobby, PetAdoption, RelationshipMilestone, and PersonalSetback. Eligibility uses profession, goals, age/life-stage configuration, prior events, and `MIN_LIFE_EVENT_GAP_DAYS`. Seeded selection occurs only among eligible templates. The event persists before mood, relationship, memory, post, or message intents. Detailed career/economy progression is deferred.

## 15. Catch-up simulation

### Rule CATCH-01: process offline time efficiently

- **Purpose:** Advance a believable world after inactivity without simulating every minute.
- **Inputs:** Last simulated game/UTC time, current UTC, world status, seed, rule version, schedules, cooldowns, pending actions, state.
- **Preconditions:** Active world; positive eligible interval; no completed run covers it.
- **Decision:** Consume at most `CATCHUP_MAX_ELAPSED_DAYS_PER_RUN`. Divide the newest `CATCHUP_DETAILED_DAYS` into `CATCHUP_BUCKET_HOURS` buckets; older consumed time uses daily aggregate buckets. For each bucket, generate eligible candidates, rank by importance then weighted deterministic score, and select only within actor/world action caps. Prioritize pending promises, romantic invitations, importance-80 events, messages/replies, relationship events, then ordinary feed activity. Hidden low-impact actions may be aggregated only when they have an auditable aggregate event.
- **Randomness:** Run seed plus bucket/actor/action substreams; rerun produces identical selection.
- **Limits:** Same per-day limits as active simulation; at most one summary item per event family/day and 20 total summary items per run.
- **Cooldown:** Normal cooldowns use game time across buckets.
- **State changes:** Commit actions bucket by bucket; advance cursor to last committed boundary. If more elapsed time remains, status is Partial and another run resumes without rerolling committed buckets.
- **Persistence:** CatchUpRun, bucket checkpoints, selected/aggregated events, relationship/memory/trend changes, summary facts, remaining interval.
- **Idempotency:** World/rule/interval/bucket keys; failed text generation does not roll back mechanics and uses fallback summary wording.
- **Example:** Ten offline days use daily aggregate buckets for the oldest three and six-hour buckets for the newest seven, subject to the same daily caps.
- **Status:** MVP; cap/time scale are open balancing decisions.

Paused time is excluded. Archived worlds do not catch up. On ordinary app inactivity while Active, the next safe run resumes from the persisted cursor. Duplicate or overlapping intervals are rejected. Partial completion never exposes an advanced cursor beyond committed mechanics.

## 16. Notifications

### Rule NOTIFY-01: create and deliver notification intent

- **Purpose:** Notify the player of meaningful world activity without duplicates.
- **Inputs:** Source event, category, importance, player involvement, read state, quiet hours, delivery settings.
- **Preconditions:** Event belongs to player's world and category is released. MVP categories are Reply, PrivateMessage, and CatchUpSummary. Follow, DatingInvitation, mention, relationship milestone, world event, trend, reputation milestone, and push are deferred unless PRODUCT.md later approves them.
- **Decision:** Priority is Critical for direct time-sensitive invitation, High for direct message/reply, Normal for follow/summary, Low otherwise. Aggregate same category/source family in a catch-up window. Push eligibility requires post-MVP opt-in, priority High/Critical, and daily cap.
- **Randomness:** None.
- **Limits:** One notification per source event/category; deferred push cap.
- **Cooldown:** Quiet hours delay non-Critical push, not in-app persistence.
- **State changes:** Unread -> Read; expiry hides but does not delete source history.
- **Persistence:** MVP persists the in-app Notification intent with source event, priority, created/read/expiry times and deduplication key. Provider delivery attempts apply only to deferred push delivery and are not an MVP requirement.
- **Idempotency:** Player/source-event/category key.
- **Example:** One persisted reply creates one unread in-app notification; catch-up retry creates no duplicate.
- **Status:** Basic in-app MVP; rich history/push deferred.

## 18. AI wording contract

AI requests may contain only the persisted decision contract: actor voice attributes, action type, target references allowed by visibility, decided topic, stance, tone, intent, reason codes safe to reveal, maximum length, and up to `MAX_MEMORIES_PER_AI_REQUEST` authorized memories. Full conversation history, hidden secrets, mechanical formulas, provider secrets, and unrelated private data are excluded.

AI output is validated against the action type and length. It cannot add actors, change visibility, declare an unrecorded follow/reaction/date/breakup, disclose an unauthorized secret, or contradict the outcome. Invalid or failed output produces deterministic fallback text and no mechanical rerun.

## 20. Open Balancing Decisions

These values or policies require playtesting or an accepted product decision. Implementations must use the listed initial constants while keeping them configurable by rule version; they must not silently choose new values.

1. Confirm or change `GAME_TIME_SCALE`, active tick length, catch-up detailed horizon, and 30-day per-run cap.
2. Decide how the UI handles more than one partial catch-up run and very long absences.
3. Tune character/day and world/day action limits for a cast of approximately 10.
4. Tune activity, post, reply, reaction, follow, opinion, mood, and goal formula weights.
5. Validate relationship starting values, impact matrix, multipliers, per-event caps, and daily caps.
6. Validate friendship thresholds and whether BestFriend should remain a derived label.
7. Tune romantic eligibility, acceptance, breakup pressure, invitation cooldown, and reconciliation values.
8. Decide age rating, romance/content boundaries, compatibility representation, and mature-theme policy before enabling romance broadly.
9. Decide whether AI-to-AI private conversations are simulated, stored, or player-visible.
10. Decide the release placement and final rules for commitment, engagement, marriage, separation, reconciliation, and divorce.
11. Tune memory expiry, reinforcement, recall weights, and retrieval limit against AI cost and continuity quality.
12. Decide whether any synthetic follower population exists; MVP uses only actual world-local follow edges.
13. Tune trend thresholds, world/life-event frequency, and concurrent-event limits before those deferred systems ship.
14. Decide notification batching, quiet hours, expiry, push eligibility, and device-push cap.
15. Decide whether trait evolution is valuable; it remains disabled in MVP.
16. Decide whether passive relationship decay is desirable; it remains disabled in MVP.

## 21. Consistency requirements

Before accepting a rules change, verify that every released PRODUCT.md feature has a rule; deferred features remain guarded; AI controls no mechanical outcome; all random choices use persisted deterministic seeds; bounded values are clamped; significant actions persist history; state transitions reject forbidden paths; retries cannot duplicate events; and terminology/constants are used consistently. Behavioural rules require automated tests when implementation begins.
